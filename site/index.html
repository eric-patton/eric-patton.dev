How I work

Three habits, and why

Findings before changes

On a rescue job you get the written assessment first: what is broken, what is dangerous, what it costs. You can stop there and take it to somebody else. Nobody should authorise a repair they have not seen described.

Tests against the real thing

Integration tests run against a real PostgreSQL in a container, not an in-memory substitute that quietly accepts SQL the real database would reject. It is slower and it is the only version that means anything.

It has to run without me

Container builds, migrations, seeded demo data and CI, so the project starts with one command on somebody else's machine. A handover that depends on my laptop is not a handover.
